## 0. Контекст и зачем заново

Старые аудиты устарели — делаем свежий полный, прошлые находки используем только как sanity-check.

## 1. Объём

Все три компонента монорепо `github.com/anex/wg-monitor` (Go 1.26.4, ~100k строк, 29 пакетов) + доставка:

- **backend** — `internal/backend/**`: HTTP-хендлеры, alerts/dispatcher, realert, retention/VACUUM,
  db, callbacks/authz, dashboard, release_proxy, ratelimit, metrics.
- **agent** — `internal/agent/**`: cmdloop, actions (self_update, route_*, opkg, maintenance,
  update_backend_url), reporter, checks.
- **deploy** — `cmd/deploy/**`: awgm_client/relay, restore/backup, ssh, lock, github, vps_sync, secrets_io.
- **доставка** — `.github/workflows/{ci,release}.yml`, `internal/releaseorigin`, `internal/releasesig`,
  `cmd/release-sign`.
- **контракт** — `pkg/wire`.

## 2. Измерения (позиции атаки)

1. **Безопасность** — supply-chain/подпись релизов, TLS к роутерам, секреты at-rest,
   Telegram-авторизация (spoofing callback'ов), инъекции в exec/ndmc, SSRF/path-traversal, dashboard-сессии.
2. **Надёжность/конкурентность** — goroutine fanout, VACUUM-локи, гонки (topic creation),
   backoff+jitter, идемпотентность/дедуп команд, graceful shutdown.
3. **Корректность/логика** — особенно свежая работа по уведомлениям и маршрутам, partial-success, FSM алертов.
4. **Deploy/DR** — деструктивность restore, атомарность бэкапов, таймауты ssh, pid-lock.
5. **Наблюдаемость/эксплуатация** — логи, метрики, health/readiness, алертинг на собственные SLO.
6. **Данные** — конфиг SQLite, миграции, шифрование, RPO/RTO.

## 3. Метод

- Explore-агент картирует релевантные файлы и кандидаты в находки (breadth: medium; security — thorough).
- **Каждый кандидат лично верифицируется по `file:line`** перед попаданием в отчёт — прямой ответ на
  историю ~50% ложных срабатываний от агентов-разведчиков.
- Ground-truth прогоны (выполнены 2026-06-18, коммит `23470cfd`, `CGO_ENABLED=0`):
  - `go build ./...` — ✅ OK (7.2с)
  - `go vet ./...` — ✅ чисто (2.6с)
  - `go test ./...` — ✅ зелёное, 1682 теста / 29 пакетов (19.8с)
  - `govulncheck ./...` — ✅ нет уязвимостей (6.0с)
  - `-race` — **не запускался** (нет gcc/C-тулчейна); отметить как непокрытое, рекомендовать в CI.

### Гейт качества (что попадает в отчёт)

Находка включается только при наличии всех трёх:
1. подтверждённый мной `file:line`, который я прочитал;
2. конкретный сценарий поломки (кто/как ломает);
3. конкретный фикс.

Что не воспроизведено в коде — отбрасывается.

## 4. Результат

- Один отчёт: **`docs/audit-2026-06-18.md`** (продолжение конвенции именования).
- Формат: восстановление намерения → вердикт GO/NO-GO → блокеры →
  Critical/High/Medium/Low с ID (`SEC/BE/AG/DEP/PROD`) + `file:line` → кривая логика →
  чеклист готовности → карта приоритетов для фикс-агентов.
- Нумерация ID — свежая; где находка совпадает со старой, помечается соответствие (напр. «ср. SEC-01»).
- Прошлые блокеры (подпись релизов, TLS-pinning, restore-валидация) проверяются отдельно — закрыты ли
  они 105 коммитами.

## 5. Границы

- **Только аудит, без починки кода.** Фиксы — отдельной волной после ревью находок владельцем.
- Вне репозитория и не покрывается: firewall VPS, конфиг Caddy в проде, ротация токенов в эксплуатации,
  реальная нагрузка/стресс (отмечается как «проверить вручную»).
