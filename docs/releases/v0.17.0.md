# v0.17.0

## Release Focus

The mini app becomes the operator's day-to-day console: routes are managed
from it, diagnostics answer in words, maintenance moved over from the bot,
and cabinets issue configs without the config ever passing through the
client. Then a live router corrected three guesses the code had made about
it.

## Changes

### Route management (phase C3)

- Send a destination into a tunnel: the router's catalogue by category, or
  targets typed by hand. The rule type is never asked — it is read from what
  was typed; mixed input (site names and network addresses in one rule) is
  refused on screen instead of after a round trip to the router.
- Move every rule to another tunnel, and make a policy's chain start with a
  different tunnel. Both explain the consequence before the tap, including
  the case where the promoted tunnel is switched off: the order changes at
  once, the traffic only when it comes up.
- Route command results stopped being "done". A rebind that half succeeded, a
  promotion that did not move traffic, and a change the router could not
  refresh afterwards each say so.

### Diagnostics and events (phase C4)

- The diagnostics screen opens with numbers already in it: six data rows,
  each with an answer and a measurement, built from what the router has
  already reported. A silent router answers "we don't know", not "no" — its
  readings predate the silence.
- Measurements reach the client as a whitelist of check facts, never as the
  agent's raw details blob: that blob carries router topology the mini app is
  not shown.
- Two exit addresses side by side with an explicit verdict. The same address
  through the tunnel and past it means the substitution is not working, and
  that is said in red rather than left for the reader to notice.
- Events read as news: a phrase about the consequence, the check name small
  underneath, and a duration computed from the pair (fell — came back).

### Maintenance, firmware, fleet (phases D1, D2)

- Settings screen: the thresholds the bot judges this router by (live, from
  the backend config), what is installed on the router, ping-check with a
  switch per line, two doctors, and a plain-words help section.
- Tunnels can be switched on and off where a way to do it exists — an opkg
  tunnel has no NDMS interface, and there the button is absent rather than
  greyed.
- Firmware install has two boundaries: the owner only, and the router's name
  typed by hand. The typing is not protection from a stray finger; it is the
  pause in which the consequence is read.
- Fleet screen: broken first, five dots per router — the same five services
  the router screen draws as lamps. Grey means "the router did not say", not
  "broken". One button rechecks the whole fleet and counts honestly.
- Provider cabinets (Amnezia Premium, HideMy.name): the client sends only the
  choice; the server fetches the config and hands it to the agent. That is
  why `tunnel_import` stays out of the mini-app allowlist.

### Traffic (phase F)

- `tunnel_traffic` brings the router's own exchange series. The volume is the
  router's own number: points carry rates, and a sum of rates is not a volume.

### What the live router corrected

- Traffic points carry unix seconds and byte-per-second rates, not RFC3339
  strings and counters. The old shapes would have failed to parse at all.
- A created rule's id is assigned by the router; the action used to return the
  plan's synthetic key, so anything done with that id answered "not found".
- Bind names differ in case between the routing catalogue and a created rule,
  so the reconciliation step never found the rule it had just created.
- The same target arrives twice (domains and manualDomains) and used to be
  printed twice in delete previews.
- On 2.17.2+r21 presets are described with sing-box rule sets; twelve of 87
  cannot be expressed as a DNS/HR-Neo rule. They are not offered, and their
  count is stated rather than silently dropped.

### Mixed-version fleet

- The presets envelope changed between router builds; all three shapes are
  understood, because an unparsed envelope means an empty catalogue on screen.
- A build without the traffic endpoint says so in words instead of showing an
  HTTP 404.
- An agent older than the app answers "unknown action"; the screen translates
  that into "this router's agent is older than the app".

### Known gap

- `route_rebind` on a policy-model router rewrites policy rules into
  interface bindings when the source tunnel carries the default-route flag.
  Until that is fixed in the agent, the mini app offers "move everything"
  only where a tunnel has rules of its own.
