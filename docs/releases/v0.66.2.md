# v0.66.2

## Release Focus

This patch makes the Tunnels tab faster and keeps its status payload focused on
the facts that are actually rendered there.

## Highlights

- The Tunnels tab now requests a dedicated compact `tunnels_status` snapshot
  instead of downloading the complete route-target catalog on every refresh.
- Tunnel health, policy counts, default egress, AWG Manager evidence and
  freshness remain in the compact snapshot, so the UI keeps the same status
  semantics while transferring less data.
- Canonically equivalent route targets are deduplicated before status snapshots
  and route plans are assembled, preventing duplicate route details and writes.
- The full `route_status` action remains backward-compatible for screens and
  diagnostics that need the complete route catalog.
- If an older agent does not know `tunnels_status`, the tab retries once with
  `route_status`; mixed-version and sleeping fleets therefore keep working
  during rollout.

## Verification

- Agent action tests cover compact and full snapshots independently.
- Mini-app render tests verify that tunnel refreshes use `tunnels_status` and
  preserve the existing status, import and removal flows.
- The standard release workflow publishes signed checksums, binaries and SBOM.
