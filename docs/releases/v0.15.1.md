# v0.15.1

## Release Focus

The bot's private-chat menu button opens the mini app.

## Changes

- `setChatMenuButton` now installs a `web_app` button ("Открыть приложение")
  pointing at `<public_base_url>/miniapp/` whenever `public_base_url` is an
  HTTPS URL. Without it — or on plain HTTP, which Telegram refuses to open as a
  web app — the previous `commands` menu stays.
- The button is still re-applied on every backend start, which is the point: a
  button set by hand in BotFather was silently reverted by the next restart.
  Now the configured mini-app URL is what wins, and BotFather is not part of the
  loop.
- Group and forum-topic surfaces are untouched: Telegram renders the chat menu
  button only in private chats with the bot, so per-topic reply keyboards,
  inline fallbacks and `setMyCommands` behave exactly as before.
- Release build no longer installs UPX from `apt`. `apt-get update` on the
  hosted runners stalled for tens of minutes often enough to lose two v0.15.0
  build attempts, one of them 55 minutes on a single matrix leg. UPX now comes
  from its own GitHub release, pinned by sha256.

## Verification

- `go vet ./...` — clean.
- `go test ./...` — 31 packages ok; the one failure is the known macOS-only
  `cmd/deploy TestDiagnosisFromReport_RouteElevationHint`, green on Linux CI.
- New tests: `TestSetWebAppMenuButton_PostsWebAppButton` and
  `TestSetCommandsMenuButton_OmitsWebAppFields` (payload shape — Telegram
  rejects a `commands` button that carries `text`/`web_app`), plus
  `TestMiniAppMenuURL` for the URL/scheme rules.
- Live fleet at release time: backend `v0.15.0` on the Raspberry Pi behind
  KeenDNS, eight agents reporting, `testkeen` already on `v0.15.0` with 7/7
  checks green and seven older agents on `v0.14.x` unaffected.

## Upgrade Notes

- Nothing to configure. If `public_base_url` is already the HTTPS backend
  domain, the button switches over on the next backend restart.
- To keep the slash-command menu instead, there is no flag — the mini app is
  the intended surface. Clearing `public_base_url` would also disable the alert
  "Open in app" buttons, so that is not a workaround.
