# v0.18.0

## Release Focus

The last item of the mini-app programme: replacing a tunnel's config from the
phone, as a six-step job with a rollback at every step. Plus the switch that
was missing under half the fleet's tunnels.

## Changes

### Config replacement wizard

- A job, not a chain of calls from the screen: the operation outlives the app
  being closed, and the rollback has to stay reachable from another device.
  It lives in the same store the provisioning engine uses, so a router cannot
  be reinstalled and re-configured at the same time.
- Six steps: issue the config at the provider, import it as a NEW tunnel
  beside the old one, wait for a handshake, make it the policy's first link,
  check the exit address, and only then switch the old tunnel off.
- The old tunnel is never deleted. It is switched off and stays. A test
  asserts `tunnel_delete` never reaches the agent on any path.
- A handshake is not the success criterion — it happens on tunnels that pass
  no traffic. The verify step asks for the exit address through the tunnel and
  past it and demands they differ. Same address means the rollback puts the
  policy back on the old tunnel.
- One replacement per router. A second attempt gets "already running" rather
  than a validation error, and the screen shows the running job instead of a
  button.
- Where a tunnel's config came from is now remembered (`tunnel_config_origin`:
  provider, variant, when). Tunnels created by hand have no row, and that is
  an honest "unknown" rather than a gap.
- When it ends — success, failure or rollback — the bot writes into the
  router's topic. The app cannot wake someone who has not opened it.

### Tunnel power by id

- `tunnel_power {tunnel_id, on}` switches a tunnel through awg-manager rather
  than ndmc. The old `tunnel_enable`/`tunnel_disable` pair only ever worked
  for NDMS interfaces, and half of the live router's tunnels are opkg ones
  with no NDMS name at all — there was no way to switch them off from the bot
  or the app. The wizard needs it for its start and rollback steps; the screen
  needed it so the button exists under every tunnel.

### Fixes found on the live router

- See v0.17.x for the traffic payload, the created rule's id, bind-name case,
  duplicated targets and the mixed-version fleet. This release adds the
  rebind mine's live proof: a sandbox rule moves and comes back while 26
  policy rules stay untouched.
