# v0.15.0

## Release Focus

The Telegram Mini App becomes a real operator surface, and the routing screen
starts telling the truth about where traffic actually goes.

This is the first release carrying the mini-app program's phases A (shell and
design system) and B (routing truth), on top of the mini-app foundation and
alert actions that had accumulated since `v0.14.4`. The VPS dashboard is
untouched and stays as the fallback entry point.

## Changes

### Mini app — shell and design system (phase A)

- Own palette and dark theme derived from the design mock; Telegram's theme now
  only selects light or dark instead of supplying colours. Palette lives in one
  place (`miniapp/src/theme.js`) and a test keeps `style.css` in sync with it.
- Shell rebuilt as header + four bottom tabs + overlays + bottom sheet:
  Router, Routes, Diagnostics, Events. Navigation is a pure reducer (`nav.js`).
- Router screen redrawn as a live instrument: tunnels, traffic, check lamps
  with a legend, action tiles, and a confirmation sheet for commands.
- New Events tab: per-router timeline from the backend.
- Alerts speak plain language — what happened, what it means, what to do —
  with compact action buttons and a 44 px minimum touch target.
- Admin-only access management overlay: add/remove operator, unbind owner.

### Mini app + agent — routing truth (phase B)

- Rule-to-tunnel binding is read from awg-manager's **access policies** instead
  of the per-rule field that live routers leave empty. A policy's rules are
  credited to its active tunnel and to no other, so counts stop multiplying
  across the fallback chain.
- Policy chains are shown as priority: which link is active, which are reserve,
  which are unavailable. A policy whose egress leaves the VPN is labelled
  honestly ("мимо VPN"), and a policy with no interfaces says so.
- `route_status` snapshots carry `policy_model`, `active_tunnel_id`,
  `tunnel_id`/`via_vpn` per chain link, and `restart_method`. All additions are
  `omitempty`: an older agent's snapshot still renders through the legacy path
  in both the bot panel and the mini app.
- Tunnel restart goes through `/api/control/restart?id=` — the only path that
  works for opkg tunnels, which carry no NDMS name. `ndmc` remains the fallback
  for awg-manager builds that predate the endpoint.
- Importing a tunnel adds it to the HydraRoute policies via `permit`, and the
  postcondition is verified by re-reading policies **past the NDMS cache**
  (`?refresh=true`) rather than trusting `success:true`.

### Security / toolchain

- Go toolchain moved to **1.26.6**: `go 1.26.5` carried five stdlib advisories
  reachable from our code (`net/url`, `crypto/tls`, `net/http` ×2,
  `encoding/asn1`), all fixed in 1.26.6, and they would have failed the release
  preflight.
- `golang.org/x/mod` bumped `v0.37.0 → v0.40.0` (GO-2026-6179, GO-2026-6180).
- `govulncheck ./...` now reports zero vulnerabilities affecting this code; one
  advisory remains in a required module (`golang.org/x/crypto`) with no fixed
  version published and no call path from here.

### Routes tab copy

- A tunnel row no longer prints the same number three times.
- The blocking-bypass engine is called "HR Neo" — the name the router's own UI
  uses — so it no longer collides with the router's policy literally named
  "HydraRoute".
- The green "основной маршрут" badge no longer sits on a disabled tunnel:
  `default_route` is a setting, not a fact, and liveness is judged by `status`
  (snapshot `enabled` answers a different question and is deliberately widened
  from the NDMS routing catalogue).
- The traffic verdict no longer declares the main tunnel unknown because of
  disabled claimants; rule groups are titled in words rather than
  `policy:<name>`; empty WAN/system rows are out of the tunnel list.

## Upgrade Notes

- **The backend is fleet-wide.** The mini app is embedded in the backend binary
  (`internal/backend/miniapp_static`, served at `/miniapp/`), so updating the
  backend updates the app for every router at once. There is no per-router
  backend.
- **Agents can be rolled out one router at a time.** Snapshot fields added here
  are additive; the bot panel and the mini app both keep an explicit branch for
  snapshots from older agents.
- The only backend→agent message shape that changed is `tunnel_restart`, which
  now carries `{tunnel_id, ndms_name?}` instead of `ndms_name` alone. An older
  agent reads `ndms_name` and behaves exactly as before.
- The mini-app button is built as `<public_base_url>/miniapp/?router=<id>`; the
  bare domain root does not serve the app.
