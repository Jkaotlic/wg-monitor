# v0.13.0-rc21

Release focus: deploy-wizard resilience during flaky VPS access and safer router tunnel diagnostics.

## Highlights

- Added a resilient wizard API client: HTTPS is still the primary path, but transport failures can fall back through SSH to the backend on `127.0.0.1:8080`.
- Kept real backend/API errors visible: HTTP failures such as bad auth or validation errors are not masked by the SSH fallback.
- Reused the same resilient client for enrollment, VPS sync, doctor heartbeat checks, deploy metadata push, and pull-based agent updates.
- Fixed the tunnel connectivity action so it prefers the HydraRoute-matching tunnel instead of blindly picking the first/default tunnel.
- Added a multi-workspace VPS implementation plan for hosting multiple isolated Telegram bot/group/customer fleets on one VPS.
